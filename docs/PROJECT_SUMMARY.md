# 项目说明与讲解提纲

更新日期：2026-10-27。项目定位：完成核心功能与基础评估的本地 LLM 数据分析学习原型。最终审核与演示已获用户确认，人工结论已写入独立快照，本阶段收尾完成。

## 可以怎样介绍项目

LLM Data Analysis Copilot 允许用户上传 CSV，用自然语言询问数据规模、描述统计、分组聚合或相关性。模型负责理解问题和提出工具参数；Python 在本地持有 DataFrame，校验请求后用 Pandas 执行真实计算，再把结果交给模型解释。应用通过 FastAPI 提供上传分析接口，Streamlit 提供页面。

它解决的是“把自然语言问题连接到可核对的统计计算”，不依赖模型自行心算，也不允许任意代码执行。仅有结构化输出或 HTTP 200 并不能证明回答正确，因此项目另外提供工具数值检查和人工回答审核。

## 关键设计及原因

| 设计 | 原因 |
| --- | --- |
| Python 持有 df，模型只生成可序列化参数 | 明确数据与执行的归属，不让模型构造 DataFrame 或读取任意路径 |
| 工具白名单和本地校验 | Schema 是生成约束，不能取代执行前校验 |
| tool_call_id 匹配调用结果 | 同一工具可重复调用，工具名不能唯一标识一次请求 |
| 有限轮工具循环 | 支持依赖前轮结果的分析，超限时明确停止 |
| 统计函数、服务、HTTP、页面分离 | 同一统计与分析服务可被命令行、接口和测试复用 |
| null 和状态配合返回 | 区分无法计算与真实的数值零，避免错误统计解释 |
| 上传限量读取及服务端临时路径 | 控制应用读取大小，防止用上传文件名覆盖路径，退出后清理 |
| 自动评估与人工快照独立 | 工具正确不等于正文正确，审核过程保留原始证据 |

## 已有证据，如何准确表述

- 2026-10-27 最终工程检查：755 项离线测试、Ruff、mypy、格式和 pip check 通过。它们覆盖工程与业务边界，不代表 755 次真实 LLM 验收。
- 七个固定真实评估案例使用 qwen3.8-flash，2026-10-26 自动检查 7 通过、0 失败；不能据此宣称系统准确率 100%。
- 最终人工审核快照记录 7 通过、0 失败、0 待审核。前两项由用户命令行记录，其余五项根据用户最终确认通过脚本写入新文件；不能把该小样本人工结论当成系统总体质量指标。
- 页面和接口已分阶段人工验收，最终演示已获学习者确认。未实测新建环境全量安装、负载或生产部署。

## 个人实现与协作边界

学习者从模型 API 调用开始编写核心学习代码，逐步完成提示词、结构化输出、Function Calling、有限轮服务、HTTP/上传接口、前端和评估/审核脚本，并进行理解检查及真实运行。

Codex 完成基础工程与非 LLM 统计模块，负责离线测试、审查、解释及文档整理；在明确授权下协助修复依赖声明与代理等问题。介绍项目时应如实说明这种协作，避免声称全部代码和测试均独立编写。也不要将使用过的学习实验误称为生产功能。

## 需要能讲清楚的问题

1. 为什么模型调用 dataset_info 时参数可以是空对象，而 Python 仍能使用 df？
2. 为什么模型工具 Schema、Python 参数校验、HTTP 响应模型不能互相替代？
3. 为什么 Pearson 的 36 对样本不同于两列各自的 38 个非缺失值？
4. 为什么全缺失组 sum=null，而 5 与 -5 求和等于 0？
5. 为什么超时是 504，上游模型认证失败由当前后端映射为 502？
6. 为什么代理可能让“后端已停服”表现为 502，项目怎样避免错误归因？
7. 为什么工具自动检查通过，但人工仍可能判回答失败？

## 可公开描述的边界

没有跨请求会话、数据库持久化、用户鉴权、任意代码执行、RAG 或生产部署。数据类型及 NA 由 Pandas 推断；模型可能产生结构合法但无意义的文本。当前案例数较小，成本、时延、采样稳定性及不同数据分布尚未系统评估。后续扩展另立任务，本次收尾不新增业务能力。
